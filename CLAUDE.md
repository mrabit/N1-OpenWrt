# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in this repository.

## Project Overview

This repository is a customization and packaging layer for ImmortalWrt-based bypass-router images. Upstream ImmortalWrt is cloned during the build; this repo provides three build **profiles** that share one service stack:

- **N1** (`armsr/armv8/N1/`) — Phicomm N1 (Amlogic S905D), packaged by ophub into a flashable `*.img.gz`, ships `luci-app-amlogic`.
- **x86** (`x86/64/`) — x86/64 generic, OpenWrt emits a bootable `*-generic-squashfs-combined-efi.img.gz` directly (no ophub), no `luci-app-amlogic`.
- **armvirt** (`armsr/armv8/armvirt/`) — ARM64 generic VM (UTM/QEMU on Apple Silicon, any EDK2/UEFI aarch64 hypervisor). "armvirt" is the ARM-community/legacy-OpenWrt name for an ARM VM image; the filename's board segment stays `armv8`. Same `armsr/armv8` target as N1, but like x86 emits the combined-efi image directly (no ophub, no `luci-app-amlogic`, no on-board WiFi). virtio net/console/block/pci/mmio are all builtin (`=y`) in the armsr 6.12 kernel, so no `kmod-virtio-*` packages exist to select.

All profiles build from one unified workflow: `.github/workflows/build.yml`. A matrix `build` job compiles N1, x86 and armvirt in parallel; a single `release` job then publishes **one combined release per build** (`firmware_<date>_<time>`, all images as assets in one place; no rolling `latest`). The stamp is minted once in `setup` and read back out of the image filename by the release job, so tag + notes always match the images to the second. N1 images are **additionally** pushed to the fixed `OpenWrt` tag that `luci-app-amlogic` OTA reads — the split keys off `_s905d_`, which only N1 carries, so 晶晨宝盒 can't offer the wrong image. That release is fully reset each run (`gh release delete --cleanup-tag` drops release **and** tag) then recreated at the current commit, so the OTA tag always points at the freshest N1 image. `workflow_dispatch` takes a `profile` input (`all`/`N1`/`x86`/`armvirt`).

Shared, arch-agnostic pieces live in `common/`:

- `common/files/` — the rootfs overlay (network, `99-bypass-router`, AGH yaml, PassWall rules), used by all profiles.
- `common/config.services` — the shared package selection, appended onto each profile's `.config` before `make defconfig`.
- `common/diy.sh` — shared feed/source patches (`luci.patch`, drop attendedsysupgrade). `common/luci.patch` lives here too.

Each profile keeps only its target/rootfs/kmod-specific `.config`; N1 additionally has `armsr/armv8/N1/diy.sh` (sources `common/diy.sh`, then clones `luci-app-amlogic`). x86 and armvirt use `common/diy.sh` directly.

The current image direction is bypass-router mode with a bundled service set (PassWall + AdGuardHome + SNMP + KMS + EasyTier) rather than a full-featured OpenWrt distribution. Service business config — PassWall's node (`socks://192.168.0.8:1180`) + shunt rules, AdGuardHome's yaml, SNMP/KMS enablement — is baked into `common/files/`, so flashing produces a ready-to-use router. The `99-bypass-router` amlogic block is guarded by `[ -f /etc/config/amlogic ]`, so it self-skips on x86 and armvirt.

## Build Flow

All profiles follow the same recipe (the GitHub Actions workflows are authoritative):

1. Clone `immortalwrt/immortalwrt` at `openwrt-25.12`
2. Run the profile's `diy.sh` (N1 → `armsr/armv8/N1/diy.sh`; x86/armvirt → `common/diy.sh`)
3. Replace upstream `openwrt/files` with `common/files` (plus the profile's own `files/` if it has one), and `openwrt/.config` with the profile's `.config` + `common/config.services` concatenated
4. `make defconfig`, then `make download`, then compile with `make -j$(nproc)+1` (fall back to `make -j1 V=s` on failure)
5. **N1 only:** package the `*rootfs.tar.gz` into a flashable `*.img.gz` via `bin/package.sh`. **x86/armvirt:** the combined-efi image is already bootable; just publish it.

The N1 matrix leg expects a `rootfs.tar.gz` artifact (fed to ophub); the x86/armvirt legs each expect a `*squashfs-combined-efi.img.gz` (from `x86/64` and `armsr/armv8` respectively).

**Unified image naming.** Both the workflow and the `bin/` scripts rename the final image (in `out/<profile>/` for the workflow, `dist/` for `bin/`) to one scheme so all profiles look alike in a release:

- N1: `immortalwrt_25.12_s905d_k<kernel>_<date>_<time>.img.gz`
- x86: `immortalwrt_25.12_x86_64_k<kernel>_<date>_<time>.img.gz`
- armvirt: `immortalwrt_25.12_armv8_k<kernel>_<date>_<time>.img.gz` (profile named `armvirt`; board segment stays `armv8`, the arch)

Structure is `immortalwrt_<op>_<board>_k<kernel>_<date>_<time>.img.gz`, `<time>` = `HHMMSS` (no `:` — git tags and filenames reject the colon):

- **`<op>`** — from the built tree's `include/version.mk` (`VERSION_NUMBER`, `-SNAPSHOT` stripped). Every name site parses this and **falls back to `REPO_BRANCH`** (`openwrt-25.12` → `25.12`) if unreadable. The `release` job has no tree, so it derives `OP_VERSION` from any collected image's 2nd `_`-field (after the rename every profile carries `<op>` there, so all agree).
- **`<kernel>`** — N1 from ophub's own filename (flippy kernel, ~`6.12.48`); x86/armvirt parsed from the target `.manifest` (`^kernel` line, ~`6.12.103`). Different kernels by design.
- **`<date>_<time>`** (`2026.08.21_143005`, dotted date + `HHMMSS`) — minted **once** in `setup` (`TZ`-aware) and passed to all three legs, so every image in a run shares the same second; the `release` job reads it back off the filename tail. Locally each `build-*.sh`/`package.sh` mints its own. The images are the single source of truth for tag + notes + names.

**N1 OTA constraints (load-bearing).** The `s905d_k6.12.NN` segment must survive any rename: `luci-app-amlogic` OTA matches `.*_s905d_.*k6.12.[0-9]+.*.img.gz`, so that segment (real kernel number, not `k6.12.y`) and the `.img.gz` suffix are fixed — the rest is free (the `<date>_<time>` stamp lives in that free part, so it never affects OTA matching). **OTA "is there a newer build?" does NOT read the filename date** — `amlogic_check_firmware.sh` builds its check code from the release's `published_at` + kernel main line (`6.12`), and there's only ever one N1 asset on the `OpenWrt` tag, so the box always sees a fresh publish time.

**Gzip FNAME (N1 rename detail).** ophub's `gzip` records the pre-rename name (`openwrt_amlogic_…`) in the N1 image's gzip FNAME field; renaming only the `.gz` shell leaves that stale, so `gunzip -N` / GUI extractors decompress to the old name. So N1 is **recompressed, not `cp`'d** — both name sites do `gzip -dc "$src" | gzip -n > "$dst"`: `gzip -n` writes no name/mtime, so extraction strips `.gz` and the `.img` matches the shell (`gzip -dc`, not `zcat` — BSD `zcat` only groks `.Z`). x86/armvirt store no FNAME, so it's a plain `cp`.

The workflow layers a few build-speed/reliability tweaks (all matrix legs): enables ccache and persists `.ccache` (keyed per profile) + `dl/` (**one shared key across all profiles** — they download near-identical tarballs, so 3 separate dl caches wasted ~2/3 of the 10 GB repo budget) across runs via `actions/cache`; retries `feeds update -a` up to 3 times; pins third-party actions to a released tag or commit SHA.

Enabling ccache needs **three** `.config` lines, not just `CONFIG_CCACHE=y`: in `config/Config-devel.in` both `CCACHE` and `CCACHE_DIR` are prompt-gated behind `DEVEL`, so without `CONFIG_DEVEL=y` first, `make defconfig` **silently strips** `CONFIG_CCACHE=y` and gcc is never wrapped as `ccache gcc` (this bit us: every CI run cold-compiled ~92 min, caches page showed 0 ccache entries). The dir must be pinned via `CONFIG_CCACHE_DIR`, not `export CCACHE_DIR`: `rules.mk` does `export CCACHE_DIR := $(TOPDIR)/.ccache`, and a makefile `:=` assignment overrides an inherited env var. Sanity check: the saved cache should be hundreds of MB, not a few hundred bytes.

### Local build

`bin/build.sh` reproduces the workflow natively (no Docker). It is a dispatcher: with no arg (and no `$PROFILE`) it builds **all** profiles in sequence (N1, then x86, then armvirt); pass a profile to build just one. N1 failing aborts before x86/armvirt run.

```bash
./bin/build.sh          # all: N1, then x86, then armvirt
./bin/build.sh N1       # → bin/build-N1.sh only
./bin/build.sh x86      # → bin/build-x86.sh only
./bin/build.sh armvirt  # → bin/build-armvirt.sh only (ARM64 UTM/QEMU)
```

Final images land in the git-ignored `dist/` (never wiped, so all profiles coexist there); the intermediate tree lands under `$ARTIFACT_DIR/bin/targets/...` (default `/opt/openwrt-build/output/...`; set `ARTIFACT_DIR=./output` to pull it into the repo). Key details:

- The OpenWrt tree builds under `BUILD_ROOT` (default `/opt/openwrt-build`), which **must** be a native ext4/xfs/btrfs volume — virtiofs/macOS mounts corrupt OpenWrt's many small parallel writes. The script refuses to run if `BUILD_ROOT` is on virtiofs/fuseblk/nfs/cifs/9p.
- `dl/`, `feeds/`, and ccache persist under `BUILD_ROOT/cache`. Because a warm `feeds/` still carries `diy.sh`'s mutations, the script resets every cached feed repo to pristine (`git reset --hard` + `clean -fdx`) before each run, then re-runs `feeds update`/`diy.sh`. Caching `feeds/` avoids re-cloning every feed repo over the proxy on each rebuild; the workflow deliberately does **not** cache `feeds/` (ephemeral runners, fresh clone is simpler).
- **N1/armvirt:** an external Go bootstrap at `GO_BOOTSTRAP` (default `/usr/local/go-bootstrap`) is required (OpenWrt Go >=1.26 needs a >=1.24.6 bootstrap, unsupported from source on arm64). `check_go_bootstrap` **auto-installs** it when missing. x86 can build Go from source, so `build-x86.sh` uses `GO_BOOTSTRAP` only if present and never hard-fails on its absence.
- Each profile uses a separate scratch subtree (x86: `BUILD_ROOT/build-x86`, `cache/feeds-x86`, `cache/ccache-x86`; armvirt: `build-armvirt`, `cache/feeds-armvirt`, `cache/ccache-armvirt`). **N1 and armvirt share the `armsr/armv8` OpenWrt target**, so the separate `OUTDIR` is load-bearing (same `bin/targets` subdir otherwise). `publish_artifacts` wipes `ARTIFACT_DIR/bin/targets` per run; the final `*.img.gz` for each lands in `dist/`, which is never wiped.
- By default every run is a full clean build (wipes and re-clones the tree, resets feeds, re-runs `diy.sh`, full `make`) — same as the workflow, deliberate for reproducibility. ccache/`dl/`/`feeds/` only save re-downloads and repeated compile units.
- `INCREMENTAL=1` (opt-in, default off) reuses a warm tree — skips clone/feeds/`diy.sh` and lets `make` rebuild only what changed. It re-stamps the overlay + `.config` each run, so package/overlay edits **are** picked up; `diy.sh` edits are **not** (those patch pristine source — run a full build). Falls back to a full build if no warm tree is present.
- All outbound fetches default to `socks5h://192.168.0.8:1180`; override with `ALL_PROXY`. Other tunables: `BUILD_ROOT`, `JOBS`, `REPO_BRANCH`, `OPHUB_REPO`, `INCREMENTAL`.

**N1 packaging** lives in `bin/package.sh` (invoked automatically at the end of `build-N1.sh`, also runnable standalone against a prior build's `bin/targets`). It needs passwordless `sudo` (loop mount + `mkfs`) and errors out if unavailable. **x86 and armvirt have no packaging step** — `build-x86.sh`/`build-armvirt.sh` copy the already-bootable `*combined-efi.img.gz` into `dist/` and WARN if none is found (a sign the profile `.config` GRUB/rootfs symbols got flipped by `make defconfig`).

**On a shared-kernel host (OrbStack et al.)** the builtin `loop` driver runs with `max_part=0`, so `losetup -P` yields a device but never creates the `p1`/`p2` partition nodes — ophub's `remake` then fails the bootfs mount. After refreshing the ophub clone, `bin/package.sh` patches `remake` to force the nodes with `partx -d`/`partx -a` (an ioctl that ignores `max_part`) right after its `losetup` call. Guarded/idempotent, re-applied each run, WARNs if the anchor moves.

**AdGuardHome-on-emmc breakage (N1-only, verified on a real N1 flashed from a workflow image 2026-08-28).** The 晶晨宝盒 "install to EMMC" script `openwrt-install-amlogic`, while writing the emmc rootfs, runs `rm -rf usr/bin/AdGuardHome && ln -sf /mnt/${EMMC_NAME}p4/AdGuardHome usr/bin/` — it **deletes the real 32 MB binary and symlinks `/usr/bin/AdGuardHome` at p4, but never copies the binary into p4**. p4 is freshly formatted, so the symlink resolves to an **empty directory** → AGH's init.d (under ujail) execve's a directory → `Permission denied` → procd crash-loop, AGH never binds `:53`. **Not our bug** — a clean image reflashed reproduces it every time. **N1-only:** x86/armvirt boot the combined-efi image directly and never run the installer. (The neighbouring `docker` line builds the same dangling symlink, but nothing ever execve's `/opt/docker`, so it never bites.)

**The line is NOT in the ophub repo** — it ships in the **`luci-app-amlogic` repo**, and `remake` pulls it in **at run time** (it clones luci-app-amlogic and `cp`s its `root/usr/sbin/.` into `${common_files}/usr/sbin` before overlaying the rootfs). So at `package.sh` patch time the file **does not exist yet** — an earlier patch that tested for it after the ophub clone was silently dead, in CI and locally. **Current fix:** `package.sh` patches **`remake` itself** (same technique as the losetup workaround) — after remake copies luci-app-amlogic's sbin scripts, an injected `sed` prefixes the AGH line with `: #N1PATCH# `. The inner sed address `/AdGuardHome && ln -sf/` is deliberately slash- and backslash-free so GNU sed's `a\` text doesn't mangle it. AGH's `work_dir` is `/var/lib/adguardhome`, not p4, so the binary staying in `/usr/bin` is self-sufficient. Guarded/idempotent, re-applied each run; CI runs the same script, so both package identically.

**Symptom on a flashed N1:** `/usr/bin/AdGuardHome` is a symlink `-> /mnt/mmcblk2p4/AdGuardHome` (a dir), AGH dead, `:53` unbound, `logread` shows the execve loop. First check the WARN (the anchor `luci-app-amlogic: sbin download completed` moved in remake). Do **not** "fix" it in `99-bypass-router` with a first-boot re-download: the `25.12-SNAPSHOT` apk repo is a rolling snapshot that only guarantees "latest", so the exact shipped `adguardhome` version is often already gone (`APK unavailable, skipped`) — the package-time patch is the only reliable fix.

### `common/diy.sh` + `armsr/armv8/N1/diy.sh`

- `common/diy.sh` (shared, used by x86 and armvirt directly): applies `common/luci.patch` to the upstream source; drops `luci-app-attendedsysupgrade` from the default luci collection; clones `EasyTier/luci-app-easytier` and copies its `luci-app-easytier` into `feeds/luci/applications/` and its `easytier` core into `feeds/packages/net/` (both symlinked by the subsequent `feeds install -a`); and `rm -f`s two conflicting FMSH SPI-NAND kernel backport patches (see gotcha below). Expects `COMMON_DIR` in the env (the caller exports it; falls back to its own dir).
- `armsr/armv8/N1/diy.sh` (N1): sources `common/diy.sh`, then clones `luci-app-amlogic` and copies it into `feeds/luci/applications/`.

The service set's symbols come from the stock ImmortalWrt feeds (proven by `apk add` succeeding against the SNAPSHOT repo, built from the same feeds), so no extra feed is needed — PassWall's cores (`xray-core`, `sing-box`, `chinadns-ng`, `geoview`, `ipt2socks`) are pulled in as deps by `make defconfig`. **EasyTier is the one exception** — not in the feeds, so `diy.sh` clones it. Its `easytier` core is Rust but its Makefile does **not** compile from source: `Build/Prepare` `wget`s a prebuilt release binary (`easytier-linux-{aarch64,x86_64}-v<ver>.zip`) straight into the package build dir, sidestepping the aarch64 `rust/host` build the SS-rust cores hit. **Local-build caveat:** that raw `wget` bypasses OpenWrt's curl infra and honours `https_proxy`; GNU wget can't speak `socks5h://`, so a **local** build behind the socks5 proxy may fail to fetch the binary. CI has direct internet, so the workflow is unaffected. No node/network config is baked in (mesh name + secret are sensitive, same rule as the WiFi PSK) — configure it in LuCI (VPN → EasyTier).

PassWall also defaults to `shadowsocks-rust-sslocal`/`-ssserver` on aarch64, which are explicitly disabled: they pull `rust/host`, and the OpenWrt rust package hardcodes `download-ci-llvm=true`, whose prebuilt-LLVM download 404s on aarch64 build hosts (rust CI only ships it for x86_64/aarch64-darwin) — kept off on x86 too for parity since `sing-box`/`xray-core` already cover SS.

`kmod-tun` + `luci-compat` are pulled in as deps by `make defconfig`; the EasyTier web console (`EASYTIER_INCLUDE_WEBCONSOLE`, `default y`) selects itself.

**FMSH SPI-NAND backport conflict (upstream regression, dropped in `diy.sh`, 2026-08-24).** `common/diy.sh` `rm -f`s `target/linux/generic/backport-6.12/436-…-mtd-spinand-fmsh-…FM25G01B-FM25G02B.patch` and its follow-up `437-…-Quad-IO-read-dummy-cycles.patch`. **Root cause:** ImmortalWrt's 2026-08-24 "Merge Official Source" pulled these mainline backports on top of ImmortalWrt's own Rockchip-based `hack-6.12/400-mtd-spinand-Support-fmsh.patch`, which ships a **different-layout** `fmsh.c` — 436's Hunk #1 anchor is absent, the patch fails, and `toolchain/kernel-headers` dies → `world Error 2` on **every** profile (`generic` patches must all apply during kernel-headers prepare). This sits at the `openwrt-25.12` branch **HEAD**, so re-cloning doesn't help. **Safe to drop:** no profile uses FMSH SPI-NAND flash (N1 = eMMC; x86, armvirt), and nothing else depends on 436/437's symbols. Idempotent and guarded. **Remove this block once upstream reconciles 400 with 436/437** (verify they apply cleanly or vanish again); leaving it is harmless but stale.

### `armsr/armv8/N1/.config` + `armsr/armv8/armvirt/.config` + `x86/64/.config` + `common/config.services`

Each profile's `.config` controls only its target, rootfs artifact, and arch-specific packages. N1 targets `armsr/armv8` → `rootfs.tar.gz` (for ophub); armvirt targets the **same** `armsr/armv8` → EFI combined squashfs image; x86 targets `x86/64` → EFI combined squashfs image. So N1 and armvirt share the target but diverge on rootfs artifact (`TARGZ` vs `SQUASHFS`+`EXT4`+combined-efi) and package set. `common/config.services` holds the shared service stack + common userland and is **appended** onto the profile `.config` before `make defconfig`. To reconstruct what a profile actually builds, read both files together.

**armvirt virtio (verified via defconfig).** A `make defconfig` on the armsr/armv8 tree confirmed: (A) the GRUB/rootfs symbols survive unchanged (`CONFIG_GRUB_EFI_IMAGES=y`, SQUASHFS+EXT4+GZIP kept — same names as x86); (B) virtio (`BLK`/`NET`/`CONSOLE`/`PCI`/`MMIO`) is **builtin** (`=y`) in the armsr 6.12 kernel (`target/linux/armsr/config-6.12`), so there are **no** `kmod-virtio-*` packages to select — the armvirt `.config` therefore carries **no** virtio kmod lines (an earlier draft did; they were dead); (C) the output is `immortalwrt-armsr-armv8-generic-squashfs-combined-efi.img.gz`, matching the `*squashfs-combined-efi.img.gz` glob. `make defconfig` stays authoritative on future kernel bumps — if any virtio sym goes modular, add the kmod then.

**N1 WiFi (open AP bridged to LAN, N1-only).** Shipped default: N1 broadcasts an **open AP `N1-OpenWrt`** bridged into the LAN, so wireless clients join `192.168.0.0/24` and get DHCP from the main router — same L2 as wired clients. N1's `.config` enables `kmod-cfg80211 kmod-mac80211 kmod-brcmutil kmod-brcmfmac wpad-basic-mbedtls` — deliberately **not** in `common/config.services`, since neither x86 nor armvirt has board WiFi.

The split of responsibility is load-bearing: the actual driver modules (`brcmfmac.ko` + the BCM43455-required `brcmfmac-wcc.ko` etc.) come from **flippy's kernel** — `remake` wipes `${tag_rootfs}/lib/modules/*` and extracts flippy's modules tarball, so any `.ko` these OpenWrt packages build is discarded (and would mismatch flippy's vermagic anyway). The **firmware blob + NVRAM** (`brcmfmac43455-sdio.phicomm,n1.bin/.txt`, `.clm_blob`) ship in ophub's `common-files/lib/firmware/brcm/` — N1-specific calibration, not a generic fallback. So the packages are selected **only for their userspace glue**: `kmod-mac80211` drags in `wifi-scripts` (`/sbin/wifi`, `/lib/netifd/wireless/mac80211.sh`), `iw`, `iwinfo`, `wireless-regdb` — the netifd/LuCI integration that lets the radio be detected and configured; those live outside `/lib/modules`, so the module swap leaves them intact. `@USB_SUPPORT=y` on armsr satisfies `kmod-brcmfmac`'s hard dep. The LuCI wireless page is in `luci-mod-network` (already pulled by `luci`) — there is **no** `luci-proto-wireless` package, so don't add one.

The AP config ships as `armsr/armv8/N1/files/etc/config/wireless` (a **per-profile files layer** — `armsr/armv8/N1/files/` overlays `common/files/`; `bin/build-*.sh` do this via `PROFILE_DIR/files`, and the workflow overlays `$(dirname matrix.config)/files` after `common/files`). It defines `radio0` (SDIO `path` from the real N1, band `2g`, ch1, country CN) + one AP iface (`N1-OpenWrt`, `encryption none`, `network lan`). It's a static file and **STA is deliberately absent** because (a) a complete `/etc/config/wireless` suppresses first-boot auto-generation of the junk AP (gotcha #2), and (b) an STA section carries the home WiFi's plaintext PSK, which must never enter git — a user wanting STA mode adds it in LuCI. For the AP to bridge into the LAN, `common/files/etc/config/network` makes `lan` a **bridge** (`br-lan`, port `eth0`); a wifi-iface with `network 'lan'` joins that L2. Wired LAN `192.168.0.4` and the uplink are unchanged. **Security:** the AP is open — anyone in range joins `192.168.0.0/24`; the user accepted this. If the radio doesn't appear, `wifi config` regenerates it (then re-check for the junk AP).

**Two N1 WiFi runtime gotchas (verified on real hardware, flippy 6.12.y)** — only relevant if this box is switched from the shipped AP mode to STA client mode; the AP config already avoids both:

1. **STA needs `roamoff=1` or it flaps forever** — add `/etc/modprobe.d/brcmfmac.conf` with `options brcmfmac roamoff=1` and reload the module, or the STA associates + gets a lease but ~10s later logs `Authentication timed out` + a `locally_generated reason=3` deauth, forever. Root cause is brcmfmac's **firmware background roaming** disrupting the link — not encryption or band (reproduced across SAE↔psk2 and 5G↔2.4G). This build has **no** `feature_disable` param; `roamoff` alone is the fix. `/etc/modprobe.d/` applies because OpenWrt loads brcmfmac via `modprobe`.
2. **FullMAC can't do AP+STA; a missing `/etc/config/wireless` auto-generates a junk AP** — the BCM43455 is **FullMAC** (`iwinfo` → `Supports VAPs: no`), so one wifi-iface per radio. `wifi config` would write `default_radio0` (AP mode, SSID `ImmortalWrt`, open, `lan`); adding an STA on top makes hostapd fail (`AP-DISABLED`/`wasn't started`), leaves the radio busy (`scan-failed ret=-16`), and the STA can't hold. We ship a complete `/etc/config/wireless`, so auto-gen never runs — but anyone switching to STA must delete/disable the AP iface first. Also pin `option channel` to the target AP's real channel, or sched-scan loops `Failed to initiate sched scan`.

### `common/files/`

This overlay becomes the root filesystem content in the final image, shared by all profiles:

- `etc/config/network` — baseline LAN as a **bridge** (`br-lan` with port `eth0`, static `192.168.0.4/24`, gateway `192.168.0.1`, packet steering). Bridged so the N1 WiFi AP can join the LAN's L2; identical to direct-eth0 when no wifi is attached, and stock OpenWrt's default lan shape.

- `etc/uci-defaults/99-bypass-router` — first-boot bypass-router setup (disables DHCP, enables IPv4 forwarding + software flow offloading, sets LAN-zone masquerade **per device**, sets timezone; self-deletes after success).

  - **NTP servers are deliberately NOT set here:** ImmortalWrt's `default-settings` package ships `/etc/uci-defaults/99-default-settings-chinese`, which sorts *after* `99-bypass-router` (uci-defaults run in filename order; `-`=0x2d < `d`=0x64) and `delete`s then rewrites `system.ntp.server` to its CN list (`ntp.tencent.com` / `ntp1.aliyun.com` / `ntp.ntsc.ac.cn` / `cn.ntp.org.cn`). Anything we set is clobbered, so we adopt its list and only keep the timezone set (it sets the same timezone value too, so order doesn't matter there). Diagnosed from a real first-boot N1 whose NTP list came up as the stock 4 while every other uci change survived.
  - Hardware offloading and fullcone NAT are kept off: the S905D has no hardware flow offload, and enabling `flow_offloading_hw`/`fullcone` makes firewall4 fail to load its ruleset; kept off for x86 too (generic NICs lack hw offload).
  - **LAN-zone masquerade (`firewall.@zone[0].masq`) is set per device — N1 needs `masq='1'`, x86/armvirt need `masq='0'`.** The script keys off `/etc/config/amlogic` (present only on N1). This is a single-arm bypass router with no `wan` interface (only `br-lan`), so the stock firewall's `wan`-zone masquerade never fires. Traffic PassWall routes **direct** (China IPv4 that skips the proxy) is forwarded br-lan→br-lan back to the main gateway; whether the reply path needs SNAT is device-dependent, established by hand-testing each box:
    - **N1 must have `masq='1'`.** Without it, China-direct sites are unreachable from clients behind N1 (asymmetric-reply / conntrack `[UNREPLIED]` class of failure). Enabling LAN masq SNATs direct flows to N1's own IP so the reply returns through N1.
    - **x86 and armvirt must have `masq='0'`.** On those boxes enabling masq actively breaks access (masq's double-NAT makes direct sites fail) — verified by manual testing.
    - **Do not "unify" this.** The two behaviours are contradictory and confirmed on real hardware: the same masq value cannot be correct for both. If a box's China-direct traffic breaks, flip its masq value and re-test.
    - **Diagnosis gotchas (2026-08):** (1) test **HTTPS/:443**, not just `http://` — port 80 returning 301 hides a broken :443. (2) The `conntrack` userspace tool on this build returns **0 rows despite `nf_conntrack_count>0`** — it's broken; read `/proc/net/nf_conntrack` directly instead. (3) `is_socks_wrap: not found` from PassWall 26.8.10's nftables.sh is **cosmetic** (log only), not a rule-generation failure. (4) Software flow offloading and DNS-shunt were both ruled out before masq — don't stop early.
  - The amlogic block below is guarded by `[ -f /etc/config/amlogic ]`, so it only runs on N1 and self-skips on x86 and armvirt.
  - It also re-points `/etc/resolv.conf` at the netifd-generated `/tmp/resolv.conf.d/resolv.conf.auto` (which carries the `network.lan.dns` upstreams) instead of the stock `127.0.0.1` stub — in bypass mode nothing serves `127.0.0.1:53` at boot, so leaving the stub breaks the router's own resolution (and `apk`). netifd rebuilds the auto file from `network.lan.dns` each boot, so the link self-heals.
  - It also sets `dnsmasq` `port=0` and stops/disables it so AdGuardHome can bind `:53` (dnsmasq would otherwise race it, and PassWall re-pulls dnsmasq up), and it enables + configures the preinstalled services: SNMP read-only community is restricted to the LAN (`public.source=192.168.0.0/24`), and KMS/vlmcsd is enabled (`auto_activate` left `0`).
  - It also **presets `luci-app-easytier`'s own `et_forward` field to `'etfwlan lanfwet'`** rather than hand-building `firewall.forwarding` rules. The plugin ships `/etc/config/easytier` with `auto_config_firewall='1'` but an empty `et_forward`, so its init.d only creates the `EasyTier` zone (masq) + `tun0` accept and **neither** cross-zone forward. Preset, `set_firewall` builds two named forwardings once the mesh is enabled: `etfwlan` = `EasyTier`→`lan` (a remote node reaching a device on this LAN — without it the node can **ping but not open TCP**, since ICMP rides EasyTier's userspace stack while forwarded TCP SYN hits the forward chain's default drop, verified 2026-08); `lanfwet` = `lan`→`EasyTier` (a LAN client reaching an EasyTier proxy subnet through this box). Using the plugin's own field means the plugin owns the rules' lifecycle (`set`/`delete` on every start), so no duplication and LuCI's Access Control shows both boxes checked. EasyTier disabled → no rules, but no zone and no mesh either.
  - PassWall's node + shunt rules and AGH's yaml are baked in via `files/` (`etc/adguardhome/adguardhome.yaml`, `usr/share/passwall/rules/proxy_host`) plus the uci sets above. The AGH yaml carries three bypass-oriented DNS settings: `aaaa_disabled: true` (IPv4-only proxy — AAAA would let clients take an IPv6 path around PassWall); `enable_dnssec: false` (upstream is chinadns-ng `:15353` shunting to CN DNS + proxy; most CN resolvers don't pass DNSSEC RRs, so validation would fail); `blocking_mode: null_ip` (blocked domains answer `0.0.0.0`/`::`, fail fast). Four **router-hardening** settings (2026-08): `ratelimit: 0` (the default 20 q/s **per client IP** silently drops DNS for a busy browser or downstream forwarder); `fallback_dns: [223.5.5.5, 119.29.29.29]` (used **only** when the sole upstream `:15353` fails, so a PassWall crash still resolves CN domains — answers may be polluted, accepted); `querylog.file_enabled: false` + `interval: 24h` (keep the UI query view, **never write the log to disk** — the default 90-day log is write-amplification on eMMC/SSD; it lives in RAM); `statistics.interval: 24h` (keep the charts, shrink the 90-day aggregation writes).

  - **PassWall proxy mode = GFW List, and two field gotchas (this PassWall version, verified against the local build tree's feed source).** The default proxy mode is **GFW List** — only GFW-listed domains go through the proxy; everything else (incl. China) connects directly. This PassWall has **no single "mode" dropdown** anymore; the LuCI「切换模式」buttons set a combination of list flags. `99-bypass-router` reproduces the **GFW List** button (`switch_gfw_mode` in `luasrc/view/passwall/global/proxy.htm`): `use_gfw_list='1'` + `chn_list='0'` + `tcp_proxy_mode='disable'` + `udp_proxy_mode='disable'` (Global Proxy would instead be `use_gfw_list=0`/`chn_list=0`/`proxy_mode=proxy`; `proxy_mode` only takes `disable`/`proxy` — `disable` means "unmatched → direct", `proxy` means "unmatched → proxy = global"). Two field traps that make silent dead config:
    - **`tcp_proxy_mode`/`udp_proxy_mode`/`use_gfw_list`/`chn_list` live on `@global[0]`, NOT `@global_forwarding[0]`.** Runtime `app.sh` reads them via `config_t_get global …`. An earlier version of this script wrote `tcp_proxy_mode` under `@global_forwarding[0]`, where nothing reads it — so the box silently ran the `proxy` (global) fallback. Only `ipv6_tproxy`/`accept_icmpv6`/`udp_proxy_drop_ports`/`tcp_redir_ports`/`udp_redir_ports` belong to `@global_forwarding[0]`.
    - **The domestic/direct DNS field is `direct_dns`, not `china_dns`.** `china_dns` is a dead legacy name with zero references in the current feed; `app.sh` reads `config_t_get global direct_dns 223.5.5.5:53`. A stale `china_dns=` set is silently ignored.
    - The Socks **upstream node** stores `address`/`port` **without** the `socks_` prefix (LuCI shows `socks_address`/`socks_port` but `rewrite_option` strips the prefix on save; `app.sh` reads `config_n_get $node address`). GFW List mode needs `/usr/share/passwall/rules/gfwlist` present (PassWall ships it).
  - It also writes the `luci-app-amlogic` (晶晨宝盒) config — OTA source (`amlogic_firmware_repo=mrabit/N1-OpenWrt`, tag `OpenWrt`, `.img.gz`), kernel source, `write_bootloader`/`shared_fstype`, and CPU governor. This **must** be done at first boot rather than as a static `etc/config/amlogic` overlay file: ophub's `remake` unconditionally overlays its own `common-files/etc/config/amlogic` (repo → ophub official, btrfs, schedutil) on top of the rootfs, so any static file is clobbered before the image is built. The uci-defaults runner executes after that overlay, so re-asserting the values there wins. Caveat: `amlogic_check_firmware.sh` fetches the releases HTML anonymously with bare `curl` (no token support), so `amlogic_firmware_repo` **must point at a public repo** or OTA update-checks 404 — keep `mrabit/N1-OpenWrt` public.

- `etc/crontabs/root` — scheduled `fstrim`

- `etc/nftables.d/20-mss-clamp.nft` — fw4 auto-includes `*.nft` here **inside** `table inet fw4 {}` (chain-definition area — write only `chain {}`, never wrap it in a `table`; a syntax error fails the whole fw4 load, so verify on real hardware). Defines a `forward`-hook chain (priority -150) that clamps **direct-forward** TCP SYN MSS > 1400 down to 1400, to stop a PPPoE/tunnel main gateway (MTU < 1500) from re-fragmenting client 1460-byte packets (→ reorder/retransmit/page-hang). **Scope caveat:** only forward traffic is covered; **PassWall proxy traffic is not** — tproxy diverts it at PREROUTING to local sing-box, which re-originates the connection (`output`, not `forward`), and that segment's MSS is negotiated by the egress socks peer (`192.168.0.8`), unreachable from N1. A deliberate "blind" preventive (no observed symptom); if the main gateway is all-1500/no-tunnel it needlessly shaves 1460→1400 (~4% payload) — delete the file to restore full efficiency. Verify: `nft list chain inet fw4 mss_clamp_fwd` + its `counter`.

Treat files under this tree as runtime defaults, not build-time source code.

### `bin/build.sh` (dispatcher) + `bin/build-lib.sh` (shared) + `bin/build-N1.sh` / `bin/build-x86.sh` / `bin/build-armvirt.sh`

`bin/build.sh` is a thin dispatcher: it resolves the profile from the first positional arg or `$PROFILE`. With no profile it runs **all** in sequence, aborting before x86/armvirt if N1 fails. All tunables pass through the environment.

`bin/build-lib.sh` holds all the machinery the profile builds share (~90% of the old scripts was duplicated): the common tunable defaults, the sanity checks (`check_buildroot_fs`/`check_disk`/`check_go_bootstrap`), `ensure_deps`, `setup_proxy`, `update_feeds`, `apply_overlay`, the full/incremental `do_build`, `publish_artifacts`, `print_build_time`, and `derive_op_version` (the `version.mk` parse, reused by `package.sh` too). It's a **pure function library** — sourcing sets the common defaults + defines functions but runs nothing; each wrapper drives the call order. A wrapper sets `PROFILE_DIR`, the scratch/cache names, `GO_REQUIRED` (1 on N1/armvirt, 0 on x86), a banner, and a `run_diy()` hook, then sources the lib and calls the functions.

- `bin/build-N1.sh` — scratch tree `build`/`feeds`/`ccache`, `GO_REQUIRED=1`, `run_diy(){ bash armsr/armv8/N1/diy.sh; }`; then `bin/package.sh` ophub-packages the `rootfs.tar.gz` into `*.img.gz` (into `dist/`).
- `bin/build-x86.sh` — scratch subtree `build-x86`/`feeds-x86`/`ccache-x86`, `GO_REQUIRED=0`; **no ophub step** — copies `*combined-efi.img.gz` from `bin/targets` into `dist/`, renamed via `derive_op_version`. `dl/` shared with N1; only feeds/ccache are per-profile.
- `bin/build-armvirt.sh` — same as x86 but arm64: scratch `build-armvirt`/`feeds-armvirt`/`ccache-armvirt` (the separate `OUTDIR` is essential — N1 shares the target's `bin/targets` subdir), `GO_REQUIRED=1` (a local arm64 host needs the Go bootstrap; CI cross-compiles so needs none), copies `bin/targets/armsr/armv8/*squashfs-combined-efi.img.gz` into `dist/`.

All keep the throwaway openwrt tree + caches under `BUILD_ROOT` to avoid virtiofs corruption, and route outbound fetches through `ALL_PROXY`.

### `bin/package.sh`

Standalone packaging step (also called automatically by `bin/build-N1.sh`, **N1 only**): repackages an existing `$BUILD_ROOT/build/openwrt/bin/targets/armsr/armv8/*rootfs.tar.gz` into a flashable N1 `*.img.gz` via ophub. Skips clone/feeds/compile entirely; requires a prior build and passwordless `sudo`. Sources `bin/build-lib.sh` only to reuse `derive_op_version` (sourcing has no side effects). Tunable via `BUILD_ROOT`/`ALL_PROXY`/`OPHUB_REPO`. Not used by the x86/armvirt profiles.

## Working Notes

- Preserve the current packaging flow unless a change is required by evidence.
- The overlay + service stack are shared in `common/`; edits there hit **all** profiles. Only put arch/target-specific bits in a profile's `.config` (or a profile `files/`, which layers on top of `common/files`).
- PassWall node + AGH yaml are baked into `common/files/` by explicit choice; when the node address / rewrites change, update the overlay, not just the running router.
- When modifying any `.config` or `common/config.services`, verify the package symbols still survive `make defconfig` — a profile's effective config is `<profile>/.config` + `common/config.services` concatenated.
- x86 `.config` GRUB symbols (`CONFIG_GRUB_EFI_IMAGES`, `CONFIG_TARGET_IMAGES_GZIP`) are **verified good** — a real build produced both `squashfs-` and `ext4-generic-combined-efi.img.gz` (squashfs is the sysupgrade-friendly one). The grub-bios-setup "BIOS Boot Partition under 1 MiB" line is a harmless warning (EFI boot only). `CONFIG_TARGET_ROOTFS_PARTSIZE=1024` is **required**: the default 160 MiB is too small for the bundled service stack and the build dies at `target/linux/install` with an ext4 "out of space" error. If a future package overflows it again, bump PARTSIZE and debug fast with `make target/linux/install V=s` (no recompile).
- When modifying overlay scripts, prefer idempotent first-boot behavior.
- **Firmware version display (LuCI Status → Overview「固件版本」).** Both the workflow's "Load custom config" step and `apply_overlay` bake the build date into `CONFIG_VERSION_CODE` (`%C`), so all profiles show `ImmortalWrt 25.12-SNAPSHOT <date HH:MM:SS>` instead of the git REVISION. **`CONFIG_VERSIONOPT=y` is the required master toggle** — the `CONFIG_VERSION_*` symbols aren't declared in any static `Config-*.in`; they're gated behind `VERSIONOPT` (default `n`), so without it `make defconfig` silently strips them. Only `%C` is touched — `VERSION_NUMBER` stays empty (→ `25.12-SNAPSHOT` fallback), so `derive_op_version` / image names are unaffected. The date is `date '+%Y.%m.%d %H:%M:%S'` (TZ from env, `Asia/Shanghai` in CI); the space is safe because the display path (`%C`) keeps spaces (only the `%c` filename variant transforms them) and `VERSION_CODE` never enters our image names.
- Commits in this repo do not require GPG signing (overrides the global "all commits must be GPG-signed" rule).
